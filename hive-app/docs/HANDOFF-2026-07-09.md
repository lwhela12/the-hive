## 7. The meeting system (the July 9 build)

One ritual, three surfaces — **don't let anyone "simplify" one away:**

- **Monthly Tune-up** (`/monthly-tuneup`) = the front door. 5 skippable steps, every
  answer is a real app action: HD wishes (manage/grant/add, "what's changed? did
  anyone help? mark it granted 🌟") → Hang ideas (posts to the hang board) →
  Calendar (create-event fn, "✈️ I'm out of town" preset) → **HIVE helps** (replies
  to the CURRENT MONTHLY THREAD on the 15min HIVE Helpers board — one thread per
  month named for its focus; copy celebrates tiny stranger/community kindnesses, NO
  time threshold; member-to-member help belongs on the member's wish) → Check-in
  (opens the survey via SurveyModal). Drafts + step persist across relaunch
  (`the-hive:tuneup-draft:{communityId}:{userId}`), cleared on finish.
- **Monthly Check-in: POP + Energy survey** = the filing cabinet. ONE survey holds
  everything: arrival questions (`q_name_today`, `q_feeling_today`, `q_feeling_note`)
  + energy (`q_energy_level`, `q_energy_mode`) + POP (`q_pop_progress/obstacles/
  priorities`) + carry-forward + meeting topic. Answers keyed by `response_period`
  'YYYY-MM'. Window opens **3 days before due_date** (client gate in useSurveys).
  Admin sees responses inside the survey editor (+ Meeting POP Preview with
  **📋 Copy for deck** and **📋 Copy HD wishes** buttons). The survey card lives
  under Admin → Meeting tools as "📊 Check-in questions & responses".
- **Meeting Helper** (`/meeting-helper`) = the window. In-app presentation deck
  (brand assets from `assets/`, arrow keys/edge taps), structured on **Nat's POP
  formula**: Welcome → Who's in the room (live arrival cards, polls while on slides
  1–2) → Outline → News from Nat (= PROGRESS: editable note + live wishes-granted
  kudos + helper logs) → Treasurer (live Honey Pot) → Plan the Meet Ups (editable +
  hang ideas) → Upcoming Dates → Check-in Highlights → **HummDinger Sesh** (POP
  formula + ALL members as uniform bubbles with their HD goal on ONE slide — per-
  member slides were intentionally folded in so nobody feels singled out; reintroduce
  from git history when check-in habits richen) → Wrap-Up (editable) → Thank You.
  Editable slides save to `communities.meeting_helper_notes` jsonb (migration 106).
- **Arrival Board** (`/arrival-board`) = standalone lightweight who's-here view
  (shares `useArrivalBoard` + `ArrivalMemberCard` with the deck). Reachable from the
  Meetings page; intentionally NOT in the Admin quick links.
- **Retired concepts — do not resurrect:** Queen Bee (replaced by the HummDinger
  go-around) and the Historian role (everyone manages the calendar).

## 8. Check-in reminder email (automated)

- `supabase/functions/check-in-reminder` (deployed): fires when today (in
  **America/Los_Angeles** — NOT UTC; due_date is midnight-UTC which is 5pm Pacific
  the day BEFORE, see the code comment) equals due_date − 3 days. Sends Resend email
  ("🐝 Your HIVE check-in is open — meeting July 15", button deep-links to
  `/monthly-tuneup`), in-app notification, optional Expo push. Dedup via
  `notifications.metadata` marker `{reminder_survey_id, reminder_period}`.
- **Preview mode:** POST `{"test_email": "...", "test_name": "..."}` sends one
  sample (real meeting date, no gate/dedup/notifications).
- **Scheduler:** pg_cron job `check-in-reminder-daily`, `0 16 * * *` (9am Pacific),
  calls the function via pg_net with the anon key. pg_cron + pg_net extensions were
  enabled for this. Migration 107 documents the setup (comments only — the live job
  was created via the Management API).
- Admins pin the survey due date to the real meeting with the survey editor's
  "📅 Sync to next HIVE meeting" button (meeting time − 30 min). July: meeting
  7/15 5:30pm → due 7/15 5:00pm → email fires 7/12 9am.

## 9. The disappearing-survey bug (IMPORTANT — don't regress)

Two stacked causes, both fixed July 9:
1. `app/_layout.tsx` onAuthStateChange used to tear down to a loading screen on
   EVERY auth event — including the TOKEN_REFRESHED that fires each time the app
   regains focus — unmounting any in-progress survey/wizard. Now: same-user token
   refreshes pass silently (`loadedUserIdRef` check); USER_UPDATED refreshes data
   without unmounting; only a real different-user sign-in does the full teardown.
2. `lib/navigationState.ts` APP_PATHS whitelist didn't include the meeting tools, so
   resume restored the last TAB (e.g. /admin) instead. `/monthly-tuneup`,
   `/arrival-board`, `/meeting-helper`, `/honey-pot` are whitelisted now and the
   native restore in `(app)/_layout.tsx` replays any whitelisted path.
